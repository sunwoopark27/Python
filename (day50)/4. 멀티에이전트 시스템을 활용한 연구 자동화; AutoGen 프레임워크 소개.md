인공지능 기술이 발전함에 따라, 단일 AI 모델의 한계를 극복하기 위해 여러 AI가 협업하는 멀티에이전트 시스템이 주목받고 있습니다. 이 자료에서는 Microsoft에서 개발한 AutoGen 프레임워크를 활용하여 LLM(대규모 언어 모델) 기반 에이전트들이 협력적으로 연구 작업을 수행하는 방법에 대해 알아보겠습니다.

## 1. 멀티에이전트 시스템이란?

멀티에이전트 시스템은 여러 지능형 에이전트가 협력하여 복잡한 문제를 해결하는 시스템입니다. 각 에이전트는 특정 역할이나 전문성을 가지고 있으며, 이들이 함께 작업함으로써 단일 에이전트로는 해결하기 어려운 복잡한 문제를 효율적으로 처리할 수 있습니다.

### 멀티에이전트의 장점:

- **전문성 분산**: 각 에이전트가 특정 영역에 특화되어 있음
- **병렬 처리**: 여러 에이전트가 동시에 작업 수행 가능
- **상호 검증**: 다른 에이전트의 결과를 검토하고 개선
- **확장성**: 필요에 따라 새로운 에이전트 추가 가능

## 2. AutoGen 프레임워크 소개

AutoGen은 Microsoft에서 개발한 프레임워크로, LLM, 도구, 또는 인간이 참여할 수 있는 대화형 에이전트를 구성하고 자동화된 대화를 통해 복잡한 작업을 수행할 수 있게 해줍니다.

```python
pip install autogen-agentchat==0.2.40

```

### AutoGen의 주요 특징:

- **다양한 에이전트 유형**: LLM 기반, 도구 기반, 인간 참여형 에이전트 지원
- **자동화된 대화**: 에이전트 간 자동 대화를 통한 문제 해결
- **도구 사용**: 코드 실행, API 호출 등 외부 도구 활용 가능
- **그룹 채팅**: 여러 에이전트가 동시에 참여하는 그룹 채팅 지원

## 3. API 설정 및 구성

AutoGen을 사용하기 위해서는 먼저 언어 모델 API를 구성해야 합니다. 다음은 OpenAI API를 설정하는 예시입니다:

```python
import os
import autogen

# API 키 설정
OPENAI_API_KEY = '여기에_API_키_입력'
os.environ['OPENAI_API_KEY'] = OPENAI_API_KEY

# 구성 리스트 설정
config_list = [
  {
    "model": "gpt-4",  # 사용할 모델
    "api_key": os.environ['OPENAI_API_KEY']
  },
]

# LLM 구성 설정
gpt4_config = {
    "cache_seed": 42,  # 다른 시도를 위해 cache_seed 변경
    "temperature": 0.6,  # 창의성 조절
    "config_list": config_list,
    "timeout": 120,  # 시간 제한(초)
}

```

> 참고: 실제 API 키는 환경 변수나 안전한 방법으로 관리해야 합니다. 코드에 직접 API 키를 포함하는 것은 보안상 위험합니다.

## 4. 다양한 역할의 에이전트 구성

AutoGen에서는 다양한 역할을 가진 에이전트를 생성할 수 있습니다. 다음은 연구 작업을 위한 여러 역할의 에이전트 설정 예시입니다:

### 4.1 UserProxyAgent (사용자 대리 에이전트)

사용자를 대신하여 시스템과 상호작용하는 에이전트입니다. 코드 실행이나 인간의 입력을 처리할 수 있습니다.

```python
user_proxy = autogen.UserProxyAgent(
    name="Admin",  # 에이전트 이름
    system_message="관리자. 계획 수립자와 상호작용하여 계획을 논의함. 계획 실행은 이 관리자의 승인이 필요함.",
    code_execution_config=False,  # 코드 실행 비활성화
)

```

### 4.2 AssistantAgent (보조 에이전트)

LLM을 기반으로 작동하며 특정 역할이나 전문성을 가진 에이전트입니다.

```python
engineer = autogen.AssistantAgent(
    name="Engineer",
    llm_config=gpt4_config,
    system_message="""엔지니어. 승인된 계획을 따릅니다. 주어진 작업을 해결하기 위해 Python/Shell 코드를 작성합니다.
    코드를 실행할 스크립트 유형을 명시한 코드 블록 안에 감싸야 합니다.""",
)

scientist = autogen.AssistantAgent(
    name="Scientist",
    llm_config=gpt4_config,
    system_message="""과학자. 승인된 계획을 따릅니다. 논문의 초록을 보고 분류할 수 있습니다. 코드를 작성하지 않습니다.""",
)

```

### 4.3 실행을 위한 UserProxyAgent

코드를 실행하고 결과를 보고하는 특수 목적의 에이전트입니다.

```python
executor = autogen.UserProxyAgent(
    name="Executor",
    system_message="실행자. 엔지니어가 작성한 코드를 실행하고 결과를 보고하세요.",
    human_input_mode="NEVER",  # 인간 입력 필요 없음
    code_execution_config={
        "last_n_messages": 3,
        "work_dir": "paper",
        "use_docker": False,  # 안전한 실행을 위해 Docker 사용 권장
    },
)

```

### 4.4 기타 특수 목적 에이전트

작업에 따라 다양한 특수 목적 에이전트를 추가할 수 있습니다:

```python
planner = autogen.AssistantAgent(
    name="Planner",
    system_message="""플래너. 계획을 제안하세요. 계획은 관리자와 비평가의 피드백을 반영하여 수정되며,
    관리자의 승인이 이루어질 때까지 반복됩니다.""",
    llm_config=gpt4_config,
)

critic = autogen.AssistantAgent(
    name="Critic",
    system_message="""비평가. 다른 에이전트가 만든 계획, 주장, 코드 등을 이중 확인하고 피드백을 제공합니다.
    계획에 출처 URL과 같은 검증 가능한 정보가 포함되어 있는지 확인하세요.""",
    llm_config=gpt4_config,
)

```

## 5. 그룹 채팅 기능 구현

여러 에이전트가 협업하기 위해서는 그룹 채팅 기능이 필요합니다. AutoGen에서는 `GroupChat`과 `GroupChatManager`를 통해 이를 구현합니다:

```python
# 그룹 채팅 생성
groupchat = autogen.GroupChat(
    agents=[user_proxy, engineer, scientist, planner, executor, critic],  # 참여 에이전트
    messages=[],  # 초기 메시지
    max_round=50,  # 최대 대화 라운드
)

# 그룹 채팅 관리자 생성
manager = autogen.GroupChatManager(groupchat=groupchat, llm_config=gpt4_config)

```

그룹 채팅 관리자는 에이전트 간의 대화 흐름을 조절하고, 각 에이전트가 적절한 시점에 참여할 수 있도록 합니다.

## 6. 대화 시작 및 작업 지시

설정된 에이전트와 그룹 채팅 관리자를 이용하여 작업을 시작할 수 있습니다:

```python
# 관리자 에이전트가 대화 시작
user_proxy.initiate_chat(
    manager,  # 그룹 채팅 관리자
    message="""
    지난 한 주 동안 arXiv에 게시된 LLM 응용 연구 논문을 찾아, 다양한 도메인별로 정리한 마크다운 표를 생성하세요.
    """,  # 작업 지시
)

```

이 코드를 실행하면 다음과 같은 과정이 진행됩니다:

1. 관리자(Admin)가 작업 지시를 내림
2. 계획자(Planner)가 작업 계획을 제안
3. 비평가(Critic)가 계획을 검토하고 피드백 제공
4. 관리자가 계획을 승인
5. 엔지니어(Engineer)가 데이터 수집을 위한 코드 작성
6. 실행자(Executor)가 코드 실행
7. 과학자(Scientist)가 논문 분류 및 도메인별 정리
8. 최종 결과물(마크다운 표) 생성

## 7. 에이전트 구성 변경을 통한 비교 실험

다양한 에이전트 구성의 효과를 비교하기 위한 실험도 가능합니다:

```python
# 비평가가 없는 그룹 채팅 생성
groupchat_nocritic = autogen.GroupChat(
    agents=[user_proxy, engineer, scientist, planner, executor],  # 비평가 제외
    messages=[],
    max_round=50,
)

# 에이전트 상태 초기화
for agent in groupchat.agents:
    agent.reset()

# 새 그룹 채팅 관리자 생성
manager_nocritic = autogen.GroupChatManager(groupchat=groupchat_nocritic, llm_config=gpt4_config)

# 동일한 작업 지시로 대화 시작
user_proxy.initiate_chat(
    manager_nocritic,
    message="""
    지난 한 주 동안 arXiv에 게시된 LLM 응용 연구 논문을 찾아, 다양한 도메인별로 정리한 마크다운 표를 생성하세요.
    """,
)

```

이러한 비교 실험을 통해 비평가 역할의 중요성과 결과물의 품질 차이를 확인할 수 있습니다.

## 8. 실제 활용 시나리오

### 8.1 연구 논문 분석

위 예제에서는 최근 arXiv에 게시된 LLM 응용 연구 논문을 수집하고 분류하는 작업을 수행했습니다. 이런 방식으로 다음과 같은 연구 작업을 자동화할 수 있습니다:

- 최신 연구 동향 모니터링
- 특정 주제의 논문 수집 및 요약
- 연구 결과의 도메인별 분류
- 메타 분석을 위한 데이터 준비

### 8.2 기타 활용 가능 영역

- **데이터 분석 프로젝트**: 데이터 수집, 전처리, 분석, 시각화를 여러 에이전트가 분담
- **소프트웨어 개발**: 설계, 코딩, 테스트, 문서화를 각 전문 에이전트가 담당
- **콘텐츠 생성**: 아이디어 제안, 초안 작성, 편집, 감수를 협업으로 진행
- **의사결정 지원**: 데이터 수집, 분석, 대안 제시, 평가를 다양한 관점에서 수행

## 9. 학습 포인트 및 고려사항

### 9.1 시스템 메시지의 중요성

각 에이전트의 `system_message`는 해당 에이전트의 역할과 행동 방식을 정의합니다. 명확하고 구체적인 시스템 메시지는 에이전트가 자신의 역할을 잘 수행하도록 도와줍니다.

### 9.2 에이전트 간 역할 분담

효과적인 멀티에이전트 시스템을 구축하기 위해서는 각 에이전트의 역할을 명확히 구분하고, 적절한 책임과 권한을 부여해야 합니다.

### 9.3 안전한 코드 실행

코드를 실행하는 에이전트를 구성할 때는 보안 문제를 고려해야 합니다. 가능하면 Docker와 같은 격리된 환경에서 코드를 실행하는 것이 안전합니다.

### 9.4 에이전트 수 최적화

너무 많은 에이전트는 불필요한 복잡성을 야기할 수 있습니다. 작업의 특성에 맞게 적절한 수의 에이전트를 구성하는 것이 중요합니다.
